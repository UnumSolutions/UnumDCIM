# Target-instance discovery gate

No target access is available. Complete this catalog before claiming replacement
parity or enabling write-back. Use approved test records; never infer a write
endpoint from an OData read route.

| Required evidence | Status |

| Custom fields, enums, identity matching and duplicates | Pending |
| Site/room/rack hierarchy and reference screens | Pending |
| Field ownership, ServiceNow feeds and current writers | Pending |
| Pagination, completeness markers, limits and outages | Pending |
| Write/concurrency/read-back behavior | Pending |
| Retirement, deletion and relationship semantics | Pending |
| Offline-critical workflows and promotion scope | Pending |
| Users, ports, telemetry rates and retention | Pending |
| Operator acceptance scripts and results | Pending |

For each workflow record its trigger, personas, prerequisites, sequence, approvals,
outputs, external effects, recovery and target module. For each screen record
layout, terminology, keyboard behavior and modernization. Keep credentials,
restricted vendor documents and customer data out of the repository.
